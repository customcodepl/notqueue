# infra

Adapters for the outside world: database (Drizzle, tenant-scoped transactions, RLS), Supabase Realtime, notification channels, external providers. Implements the ports defined in `application`.

- **May import:** `core`, `application`.
- **Must not import:** `api`, `app`, `i18n`.

## `db/`
- `schema/`: Drizzle tables in schema `app` (`organizations`, `venues`, `outbox_events`) and the roles their policies name (`roles.ts`). Change the schema, then `pnpm db:generate`.
- `migrations/`: SQL generated by drizzle-kit, forward-only; hand-written SQL goes before the generated part (what it needs, e.g. roles), after it, or into a `--custom` migration. Not formatted by Prettier.
- `client.ts`: the `pg` pool (transaction pooler at runtime, TLS with the pinned Supabase CA for hosted databases) and `getDb()` ([ADR-0013](../../docs/adr/0013-database-access-with-node-postgres.md)).
- `env.ts`: reads and validates the database URLs; never prints them.
- `transaction.ts`: `withTransaction` and the `Tx` type. Only the two scoped helpers and tests may call `withTransaction` (dependency-cruiser); adapters import just the type.
- `tenant-transaction.ts`: `withTenantTransaction(db, orgId, fn)`, which runs as `app_tenant` with `app.org_id` set transaction-locally ([ADR-0022](../../docs/adr/0022-database-roles-and-tenant-scoped-transactions.md)).
- `platform-transaction.ts`: `withPlatformTransaction(db, fn)`, as `app_platform` across tenants; only `unit-of-work.ts` and tests may import it.
- `unit-of-work.ts`: `drizzleTenantUnitOfWork` and `drizzlePlatformUnitOfWork`, the ports use cases run their transactions through.
- `venue-mapper.ts`: venue rows to the domain `Venue` and back; rejects locale codes `core` doesn't support.
- `database-health.ts`: `drizzleDatabaseHealth`, the `DatabaseHealth` port behind `/api/v1/health` (`select 1` with a timeout).
- `outbox.ts`: `drizzleEventOutbox(tx)`, the `EventOutbox` port bound to the caller's transaction ([ADR-0006](../../docs/adr/0006-transactional-outbox.md)).
- `migrate.ts`: `pnpm db:migrate`; on the local stack it also sets the local password of `notqueue_api`.
- `seed.ts`: `pnpm db:seed`, one demo tenant on the local stack only.
- `testing/`: helpers for integration tests (`*.int.test.ts`): owner connection, rolled-back transactions, global setup ([ADR-0012](../../docs/adr/0012-integration-tests-on-supabase-local-stack.md)), and the two-tenant isolation harness: `seedTwoTenants`, `asTenant`, `asPlatform` and the `TENANT_TABLES` registry. A new tenant table goes into the registry; `isolation.int.test.ts` fails until it does.

## `observability/`
- `sentry.ts`: options shared by the server, edge and browser Sentry SDKs (errors only, EU host, no PII collected).
- `scrub.ts`: `beforeSend` and `beforeBreadcrumb` scrubbers, the second line of defence against PII.
- `report-error.ts`: `reportErrorToSentry`, the `ErrorReporter` port used by the API for 5xx errors.

## `time/`
- `system-clock.ts`: `systemClock`, the real `Clock`. Wired only in the composition root (`src/server/`); tests use `FakeClock`.
